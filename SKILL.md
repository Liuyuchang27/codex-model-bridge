# Codex Model Bridge

This is an experimental gateway and verification kit. Read [README.md](README.md) for the current implementation boundary and upstream source evidence.

## Configure and test

- Run scripts relative to this skill folder. Node.js 24.14 or later is required for the dashboard; no npm packages are needed.
- Start with `npm test`, which uses local mock upstreams and consumes no provider credits.
- For actual Codex checks, generate the deliberately minimal probe catalog with `scripts/probe-catalog.mjs --openai-catalog <current-native-catalog> --client-version <installed-version> --out-dir <private-directory>`. Then run `codex-cli-probe.mjs` or `codex-session-probe.mjs` with `--codex`, `--session`, `--catalog`, `--work-dir` and `--receipts-dir`. The session path is the private local metadata file created by the native-key launcher; read it only inside the scripts, never print it. The session probe requires both configured providers. Use a dedicated scratch work directory. These probes use real API tokens.
- For the dashboard, start `node scripts/start-dashboard.mjs --codex <installed-cli>`. Read the private connection file only inside local tooling to open its one-time bootstrap URL; never print its token or full contents. Have the user submit keys on the local masked-input page. On macOS, the explicit save checkbox stores keys in login Keychain and reloads them after restarts; it requires Xcode Command Line Tools to build the small Security.framework helper. Other systems currently use memory only. Never put keys in argv, project files or tool output. Usage is saved separately without prompts or credentials and grouped by model alias over all historical records. Keep this requested gateway running after completing the task.
- When using the legacy bounded test window on macOS, use `scripts/test-session.mjs --session-dir <private-runtime-directory> --receipts-dir <receipts-directory>` to open the native masked-input window. It supports either or both providers, keeps provider keys in memory, and automatically runs a bounded live test suite. Do not inspect the child process stdout, take screenshots of the credential window, or log raw form values. The script outputs safe diagnostics only. With an inherited network proxy, use a Node runtime supporting `--use-env-proxy` and include localhost in `NO_PROXY`.
- Use `config.example.json` as the basis for a local `config.json`. Provider keys and the local bearer token are environment-variable references. Have the user provide credentials through a local hidden terminal prompt or an available secure key setup flow; never ask for a key in chat or include it in a command argument, generated document, or repository.
- If the user requests a new OpenAI key and a Platform key setup tool is available, use that secure setup flow. If the user provides an existing key, use the native local input window. Confirm separately whether that key's API project belongs to the organization receiving the credit grant; the key text does not prove organization or billing eligibility.
- Start the process with `node scripts/bridge.mjs config.json`. The gateway binds only to `127.0.0.1`; keep it running while probing.
- Use `node scripts/probe.mjs --config config.json --model <alias>` for one small routed request. `--direct` makes one baseline API request instead. These calls can consume billable tokens; the user's authorization to test applies, but does not authorize unrelated traffic or automatic top-ups.

## System proxy and network checks

The dashboard reads macOS HTTP/HTTPS system proxies at startup; explicit HTTP_PROXY/HTTPS_PROXY environment variables take precedence. Use POST /api/network/refresh or its page button to read changed settings without losing in-memory provider keys. Refuse transport resets while any API stream or network check is active. Keep loopback traffic outside the proxy and keep TLS certificate verification enabled. Do not change the user's OS proxy or selected upstream proxy node just to fix this application.

POST /api/network/check accepts a configured provider ID only and sends no credentials to its models endpoint. HTTP 401 from this unauthenticated network check means a response arrived; it does not test key validity. Use POST /api/test only after the user has submitted the intended key, and compare testedKeyUpdatedAt with the provider's keyUpdatedAt to avoid reporting an old-key test as a new-key result. Diagnostics and error messages must never contain provider keys, proxy passwords, prompts, or raw upstream error bodies.

Code upgrades to an already running old server require a one-time restart. Saved Keychain credentials reload automatically; memory-only credentials are lost. Check persistence before stopping the process and request re-entry only when necessary. Never inspect another application's memory to recover credentials. Future proxy refreshes must not require key resubmission. A successful ChatGPT connection does not establish API endpoint connectivity; test each configured API address independently. Require a completed expected reply for the page's connection test to pass; HTTP 200 with incomplete output still has recorded usage but is not a completed test.

## Interpret results

DeepSeek Flash and V4 Pro use distinct aliases but share the same DeepSeek Keychain credential. Use the model selector in the provider card to test either model. A bounded Flash → Pro → Flash history check is available with `npm run unified-probe -- <installed-cli> --deepseek-only`; it uses only the DeepSeek API, writes private receipts and does not change the user's default model. Pro is text-only in the current upstream catalog; do not copy Flash's image capabilities into it.

Report separately: local tests, real provider response, Codex client integration, and verified credit balance movement. A successful HTTP response is not proof that promotional credits were used. The official Pro API-credit benefit currently excludes Codex API-key usage; do not claim a gateway changes that rule or disguise the caller to influence billing.

This version preserves HTTP/SSE responses and tool-call history. When an upstream explicitly rejects encrypted reasoning or a nonempty reasoning-content array, it can retry once with incompatible reasoning omitted and foreign-format item IDs removed, using the same provider. Keep `call_id` pairings intact. It cannot decrypt prior state, recover an opaque compaction block, or safely discard an encrypted subagent task or item reference. Return the failure in those cases.

The small generated catalog and instruction overrides are for bounded connectivity tests. They do not prove full native-model capabilities. The dashboard can install and restore managed user-config fields through the native Codex configuration API, after a backup and schema validation. The default dashboard activation now installs a combined catalog: original official model IDs plus distinct API aliases. Its requires_openai_auth provider lets Codex supply the existing ChatGPT login; only official subscription routes forward that OAuth to the fixed official Codex endpoint. API routes rebuild headers using their own key, discarding OAuth, cookies and account/session identifiers. All requests need the independent local guard; never send or log it upstream. Keep the user config private (0600). Do not read, store, refresh or copy the user’s ChatGPT access/refresh token. Restore the original provider/catalog when the user wants official direct access. Legacy API-only activation remains an internal compatibility endpoint. The dashboard shows the saved configuration, not proof that the running desktop has reloaded it. Preserve any user-disabled catalog until the user wants API mode enabled. Never reinstate a failed catalog just to test it; validate in an isolated child first. Match the installed client version, use its bundled catalog when the local cache is stale, and publish only after native model/list succeeds. In particular, available_access_programs must be null or a valid typed object, never {}. Revalidate before activation. It does not install a login daemon or implement GPT-generated handoff summaries. Earlier CLI tools passed on 0.163.0-alpha.10.2; full catalog parsing passed on 0.165.0-alpha.1.2. The combined catalog and four-turn subscription/API continuity probe passed on 0.166.0-alpha.5.1. Use scripts/unified-probe.mjs for a bounded real test with both saved API keys and existing native ChatGPT sign-in; it uses an ephemeral, no-tool thread and does not alter config. Desktop menu visibility requires a separate restart and user check.
